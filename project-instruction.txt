# Build a Fully Functional Multi-Page Web Application: "Buffalo Political Party Predictor"

Create a polished, fully functional, interactive web application titled:

**പോത്ത് രാഷ്ട്രീയ പ്രവചനം | BUFFALO POLITICAL PARTY PREDICTOR**

This is a fun/fictional buffalo political prediction application. The application predicts which fictional buffalo political party a buffalo belongs to based on five numerical buffalo characteristics using a trained Machine Learning model.

The website must not use real-world political party symbols, logos, flags, leaders, or other political imagery. All political parties in this application are fictional buffalo-themed parties.

---

# 1. TECH STACK

Use the following architecture:

### Frontend

* React
* JavaScript or TypeScript
* Tailwind CSS
* Responsive design
* Modern animations and transitions
* Lucide React icons or similarly neutral icons
* Noto Sans Malayalam / Manjari for Malayalam text

### Backend

* Node.js
* Express.js
* REST API

### Machine Learning

The trained ML model will be provided as a `.pkl` file.

The ML model must actually be used for prediction.

Do NOT hard-code the party prediction logic in the frontend.

The frontend should send the five numerical input values to the Express backend, and the backend should pass those values to the Python ML model and return the prediction.

Recommended architecture:

React Frontend
↓
Express/Node.js API
↓
Python ML prediction service
↓
`.pkl` ML model
↓
Predicted party
↓
Express API
↓
React Result Page

If necessary, create a small Python prediction service using Flask or FastAPI.

---

# 2. IMPORTANT ML MODEL INTEGRATION

I will provide a trained `.pkl` machine learning model.

Create a clear location for the model, for example:

`backend/model/buffalo_party_model.pkl`

The application must load this model and use it for real predictions.

The five input features are:

1. **തീറ്റ ഉപഭോഗം** — Food Consumption
2. **പാലുൽപ്പാദനം** — Milk Production
3. **ചാണക അളവ്** — Dung Output
4. **കൊമ്പിന്റെ നീളം** — Horn Length
5. **സ്വത്ത് നാശനഷ്ടം** — Property Damage

All five features are numerical.

Do NOT create dropdowns for these features.

Every feature must be represented by a slider.

The slider must show:

* Current value
* Unit
* Minimum value
* Maximum value
* Clear Malayalam + English label

The minimum and maximum values must be configurable in one place so they can easily be changed to match the exact range used when training the ML model.

For example:

```text
FOOD_CONSUMPTION_MIN = ...
FOOD_CONSUMPTION_MAX = ...

MILK_PRODUCTION_MIN = ...
MILK_PRODUCTION_MAX = ...

DUNG_OUTPUT_MIN = ...
DUNG_OUTPUT_MAX = ...

HORN_LENGTH_MIN = ...
HORN_LENGTH_MAX = ...

PROPERTY_DAMAGE_MIN = ...
PROPERTY_DAMAGE_MAX = ...
```

IMPORTANT:

The input order sent to the ML model must exactly match the order used while training the model.

Do not normalize, scale, encode, or transform the values differently from the training pipeline.

If the `.pkl` file already contains preprocessing/pipeline logic, use that pipeline directly.

# 27. BACKEND API

Create an Express API:

```text
POST /api/predict
```

It should:

1. Receive five numerical features.
2. Validate them.
3. Check minimum/maximum ranges.
4. Pass them to the ML prediction service.
5. Receive the prediction.
6. Map the model's output/class index to one of the four fictional parties.
7. Return the party information.

Example mapping:

```javascript
const parties = {
  0: {
    name: "അഖിലേന്ത്യാ എരുമ സംഘം",
    slogan: "എരുമ ഒന്നിച്ചാൽ, കുളം നിറയും"
  },
  1: {
    name: "എരുമ പുല്ല് അവകാശ മുന്നണി",
    slogan: "പുല്ല് ഞങ്ങളുടെ അവകാശം, മേയൽ ഞങ്ങളുടെ സ്വാതന്ത്ര്യം!"
  },
  2: {
    name: "ദേശീയ യുവ എരുമ ഫെഡറേഷൻ",
    slogan: "ഇന്നത്തെ കിടാവ്, നാളത്തെ എരുമ നേതാവ്!"
  },
  3: {
    name: "എരുമ സ്വാതന്ത്ര്യ മുന്നണി",
    slogan: "കയറഴിയട്ടെ, കൊമ്പുയരട്ടെ"
  }
};
```

IMPORTANT:

Verify the actual class-label order in the trained ML model before using this mapping.

Do not assume that class `0`, `1`, `2`, and `3` correspond to these parties.

Make the mapping easy to modify in one configuration file.

# 28. PYTHON ML SERVICE

If the `.pkl` model cannot be directly used from Node.js, create:

```text
ml_service/
    app.py
    buffalo_party_model.pkl
    requirements.txt
```

Use Flask or FastAPI.

Example endpoint:

```text
POST /predict
```

The Node.js backend communicates with this service.

The Python service should:

1. Load the `.pkl` model once when the application starts.
2. Receive JSON.
3. Convert the five values into the exact feature format used during training.
4. Run:

```python
model.predict(...)
```

5. If supported:

```python
model.predict_proba(...)
```

6. Return the predicted class and probability.
7. Never retrain the model during prediction.
